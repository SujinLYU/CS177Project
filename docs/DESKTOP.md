# Pip 桌面版

Pip 是一个独立的 Electron 应用：小宠物可以在桌面上拖动，悬浮在浏览器和其他普通应用之上。点击宠物打开会议面板，收起面板后可以继续录音；录音状态仍会显示在宠物上。它不依赖 Chrome 扩展或 localhost 网页。

## 启动

需要 Node.js 22.12 或更新版本，建议 Node 24。首次在项目目录运行：

```bash
npm install
```

如果还没有 `.env`，将项目根目录的 `.env.example` 复制为 `.env`，填写以下配置；保留已有配置，不要覆盖已有 key：

```dotenv
OPENAI_API_KEY=你的_API_key
OPENAI_TRANSCRIBE_MODEL=gpt-transcribe
OPENAI_MODEL=gpt-4o-mini
```

然后运行开发版：

```bash
npm run desktop
```

修改 `.env` 后需要退出并重新启动 Pip。开发版读取项目根目录的 `.env`；打包版的配置位置见下节。桌面版直接由主进程调用 AI，不需要 `npm start` 或 `EXTENSION_ID`。Key 不会传给页面脚本，也不会包含在打包应用里。

## macOS 打包运行

在 Apple Silicon Mac 上运行：

```bash
npm run desktop:package
```

生成应用后，将 `.env` 配置文件复制到应用旁边的 `dist/Pip-darwin-arm64/.env`，再从 Finder 打开 `dist/Pip-darwin-arm64/Pip.app`。不要把 key 写进 `.app` 内部。

打包版优先读取 Pip 用户数据目录里的 `.env`，没有该文件时才读取 `.app` 同级的 `.env`；界面的配置状态会显示实际或预期配置路径。如果移动 `.app`，需要同时处理同级配置文件，或改用稳定的用户数据目录。打包脚本不会自动复制 key。

打包应用采用本地 ad-hoc 签名，尚未做 Apple Developer ID 发行签名或公证。

建议通过应用包启动并测试系统声音。macOS 会把系统音频权限归属于负责启动录音的进程；从终端或 IDE 启动开发版时，权限可能归属于终端或 IDE，而不是单独的 Pip。详情见 [Electron 桌面音频文档](https://www.electronjs.org/docs/latest/api/desktop-capturer)。

## 第一次录音

1. 点击桌面宠物，打开会议面板。
2. 选择同时采集麦克风与电脑声音；推荐使用耳机，避免扬声器声音又被麦克风录入。
3. 确认参会者知悉录音，再点击开始。
4. 按 macOS 提示允许麦克风和系统声音访问。若曾拒绝，进入 **系统设置 → 隐私与安全性 → 麦克风**，以及 **屏幕与系统音频录制**，为 Pip 或实际启动它的应用开启权限；按系统提示重新启动应用。
5. 说一句话，观察麦克风音量条；播放一段测试声音，观察系统声音音量条。确认两个来源都有变化后再开始正式会议。
6. 录音期间会按约 20 秒的音频段提交转写，还需等待网络与模型处理。结束时点击停止，等待最后一段和队列完成。
7. 检查并编辑转写文本，再生成摘要与任务建议。任务仍需要你查看、修改并批准，本版批准后只准备本地草稿。

系统声音采集可能包含其他应用的声音，不只 Zoom 或 Meet。当前实现把两个来源混合为一条音轨，不会自动标注说话人。

## 保存与失败恢复

- 当前录音的音频段保留在内存中，包括转写失败的段；可以重试失败段，或主动导出录音。
- 转写文本可以编辑和导出。结束录音不等于所有转写请求已经完成，请看队列状态。
- 原始音频只在主动导出时写入所选位置；退出应用会失去尚未导出的内存音频。
- 单次录音上限为一小时，以限制内存占用。长会议请分段录制并导出。
- 当前摘要步骤每次接受 20,000 个字符；超过时会提示先导出完整转写，再缩短文本进行分析，不会静默截断。
- 开始新会议前，先保存需要保留的录音和文本。桌面、网页预览与扩展不自动共享会议状态。

音频转写会将当前音频段发送给 OpenAI，摘要分析会发送你提交的文本。录音期间如遇网络、额度或 key 错误，界面应保留可重试的失败状态，不会用示例文本冒充真实转写。

## 常见问题

| 现象 | 检查方式 |
| --- | --- |
| 麦克风没有音量 | 检查输入设备、系统输入音量和麦克风权限；确认没有选到断开的耳机 |
| 系统声音音量一直为零 | 播放测试声音；检查系统音频权限；退出后从打包应用重新打开并再试 |
| 能录音但没有转写 | 检查 `.env`、API 账户额度和网络；约 20 秒后才会提交第一段，短录音在停止后提交 |
| 出现重复或回声 | 使用耳机，避免麦克风再次拾取扬声器里的会议声音 |
| 点关闭后还在录音 | 关闭会议面板是收起界面；点击停止结束录音，或从应用菜单退出 Pip |
| 电脑提示屏幕采集权限 | Electron 的系统音频入口需要显示媒体采集请求；本实现只处理音频，不保存或上传屏幕画面 |

当前使用独立 WAV 段调用文件转写接口，而不是逐字推送的 Realtime 会话。句子可能跨越段边界；生成摘要前应核对人名、数字和关键决定。音频格式和请求边界见 [OpenAI 转写文档](https://developers.openai.com/api/docs/guides/speech-to-text)。

## 验证范围

已通过 41 项自动测试，覆盖 WAV 连续分段、最后一段、权限拒绝、设备中断、转写错误和审批。另用合成麦克风与系统声音跑通真实 AudioWorklet、20 秒分段、重试与导出；没有调用真实录音设备或付费 AI。

开发版和打包后的 Pip.app 都已实际启动检查：透明置顶窗口、原生位置拖动、打开/收起会议窗口、草稿审批和状态恢复通过；应用包签名检查通过，未包含 API key。

实际麦克风、系统音频权限以及付费 AI 转写，仍需要在用户机器上按上述短录音流程验证；没有 API key 时，不应把合成音频测试视为真实语音识别成功。
